# 定制构建体积实验

[English](./size-experiments.en.md) · [定制构建指南](./custom-build.md)

这组工具用于比较源码定制构建的体积、冷加载耗时和画面变化。实验复用现有编译器与浏览器夹具，所有产物写入已忽略的 `test-results/size-experiments`。普通 `build`、定制 profile 格式、npm 发布白名单和生产渲染实现保持原有行为。

## 运行

需要 Node.js >=24、Chrome/Edge，先执行 `npm ci`。找不到浏览器时可设置 `BACLICKFX_CHROMIUM_PATH`。

```bash
npm run experiment:size
# 只比较一个配置，仍会重新构建每种方案
npm run experiment:size -- --profile=webgl2-dom
# 只比较一条路线，自动添加当前定制版作为基线
npm run experiment:size -- --profile=webgl2-dom --strategy=trail-128
# 只测构建体积，不运行浏览器
npm run experiment:size -- --build-only --profile=native-click-dom
```

完整运行比较 9 个配置与 7 种方案，共 63 个构建。配置覆盖六种后端、DOM/手动 Canvas/真实 Dedicated Worker，以及仅点击和仅拖尾。每次从当前源码重新生成全部所选构建，不用磁盘上的旧产物替代验收。

## 方案

| 名称 | 内容 | 画面要求 |
|---|---|---|
| `baseline` | 当前定制构建 | 作为对照 |
| `minified` | 在当前产物上继续优化代码、缩短变量名和去除空白 | 逐字节一致 |
| `lossless-deflate` | Paeth + DEFLATE、同步解码、可裁剪资源初始化、最终压缩 | 逐字节一致 |
| `trail-256` | 拖尾纹理均值降采样至 256²，其余沿用无损方案 | 记录真实差异 |
| `trail-128` | 拖尾纹理均值降采样至 128²，其余沿用无损方案 | 记录真实差异 |
| `procedural` | 用确定性函数生成 Trail、Circle、Ring3 | 记录真实差异 |
| `external-deflate` | 原尺寸拖尾存为独立 `trail.bin`，模块导入时加载 | 逐字节一致 |

程序化方案继续复用当前渲染管线、参数、运动算法和三角纹理，不是完整的 Lite 渲染器。纹理生成不使用粒子系统的随机数，以便保持同一输入的运动状态。

外置方案使用模块顶层 await，目标为 ES2022；构造仍同步，但导入会等待额外资源请求，失败会拒绝模块导入。当前二进制包含 RGB 与 Coverage 两个流：Native/Software 的总大小也计入其未使用的流，因此这个原型还没有实现按消费者拆分资源。

`fflate` 仅作为实验工具的开发依赖；用到解码器的产物会在 `THIRD_PARTY_NOTICES.md` 中保留它的 MIT 许可。

## 报告与验收

运行成功后生成：

- `results.json`：各构建的实际文件清单、raw/gzip/Brotli 字节数和浏览器结果。
- `browser-results.json`：每个配置/方案的逐字节对照、差异指标、计时和故障检查。
- `report.md`、`report.html`：可读表格和交互图像对照；HTML 可切换配置、方案、时刻及黑白/棋盘背景。
- 各产物目录中的 `early`、`late`、`active-trail`、`reference` PNG，以及对应的四倍差异图。仅点击或未开启合成参考时省略相关场景。

每个配置使用相同随机数、输入、逻辑时间、后端和宿主接入方式。无损路线要求哈希完全相同；有损路线记录全图和活跃区域 RGBA MAE、变化像素数及最大通道差值，不修改既有黄金数据或降低无损验收标准。全图 MAE 会被空白像素稀释，不能用作一个整体拟合百分比。

所有路线复用多实例、暂停、尺寸/DPR、清理和重复销毁检查；Worker 配置额外覆盖初始化失败、WebGL 上下文恢复，以及 WebGPU 初始化期间销毁、设备丢失和 Standard 输出降级。设备不可用或跳过会失败。

连续拖尾时，相同的 Software 产物重复运行出现过两个哈希，差异只有一个通道的两个色阶。Native/Software 的图像对照因此显式使用 `willReadFrequently: true` 的 Canvas2D 上下文；无损比较仍要求逐字节一致。性能采样另外使用默认上下文，避免把对照光栅策略的影响算成优化收益。

冷导入和初始化各测三次独立浏览器上下文；CPU 帧耗时采样 90 帧并报告 p50/p95。它包含更新及提交，不是 GPU 显存或物理显示帧率。无头浏览器的 Extended 输出也不证明物理 HDR 显示效果。

体积只统计部署 JS 和实际外置资源；分别进行 gzip/Brotli 压缩后求和。类型声明、许可证和 HTTP 请求头另计。外置方案的入口 JS 大小与资源总大小必须同时比较。

## 本轮结果

1.3.9 源码上的 WebGL2 DOM 全功能配置，结果如下。原始大小表示部署文件本身，gzip 表示压缩后的传输大小；两者均包括实际外置资源。其余配置和图像以本机报告为准。

| 方案 | 原始总 KiB | gzip 总 KiB | gzip 减少 |
|---|---:|---:|---:|
| 当前定制版 | 440.5 | 198.5 | — |
| 最终压缩 | 412.3 | 195.2 | 1.7% |
| 无损 DEFLATE | 299.5 | 145.1 | 26.9% |
| 256² 拖尾 | 251.0 | 108.9 | 45.1% |
| 128² 拖尾 | 217.7 | 83.8 | 57.8% |
| 程序化纹理 | 153.6 | 43.9 | 77.9% |
| 外置 DEFLATE | 274.7 | 143.9 | 27.5% |

Native/Software 全功能配置的无损路线分别从 194.7/203.6 KiB gzip 降到 95.4/104.0 KiB，减少 51.0%/48.9%。收益还包括移除后端不使用的 Coverage 资源初始化，不能把一个后端的百分比套到其他后端。仅点击 Native 的程序化方案从 52.7 KiB 降到 23.7 KiB gzip。

无损编码适合优先落地。降采样需要审看连续拖尾、已知背景和后期消散图像。程序化方案体积收益最大，但会改变光斑轮廓、纹理细节和溶解分布。外置方案主要减少入口 JS，并引入额外请求；当前原型的总下载量收益较小。

当前画面对照使用 320×240 读回场景；其差异指标不能直接代表所有 DPR、拖尾宽度和用户参数下的视觉变化。

本轮在 Edge 149.0.4022.69 完成全部 63 个实验构建、231 个画面采样和 42 项 Worker 故障检查，无设备跳过。无损拖尾的 RGB、Coverage、RGBA 共 2 MiB 解码数组与源码逐字节一致；外置资源在 DOM/真实 Worker 下的 404、短头和错误长度共 6 项拒绝检查通过。`npm run check` 与原有 `npm run test:custom:release` 也通过，后者的 67 个浏览器定制配置全部像素一致且无跳过。交互报告的选择器、图片加载和背景切换已检查。

这些选项属于实验命令，尚未加入生产 profile；本分支用于选择方案，不直接替换发布版本。
