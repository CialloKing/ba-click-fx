## Software 缓冲与圆环颜色复用

RGB 和按需准备的 Coverage 共用层级缓冲准备逻辑：每层保留 down，仅非末层分配 up，仅第 0 层分配 scratch。无消费者的字段使用空 Float32Array，稳定布局保持引用；层级角色变化时解除旧容量，需要时仍采用原来的容量增长策略。未更改滤波、清零或边界处理，也未清空既存的非活动层容量缓存。

圆环完整 stop 位置与 CSS 颜色序列依附当前渲染范围的采样数据。有效性包括采样数据、实际材质能量、主题上下文及 hue、透明度、明确的 clear/emission/coverage 用途和对应合成参数。不同 CanvasGradient 仍按原顺序写入全部 stop；缓存命中仅省去重复颜色求值，不复用渐变对象或图像。

位置使用 Number 双精度，重复边界 stop 的位置与顺序不变。首次准备保留原来的颜色求值/写入交错顺序，所有写入成功后才保存序列；失败不保存半成品。没有圆锥渐变支持时仍走原分段路径；独立调用不保存序列。复用既存范围的保存/finally 恢复机制，重入和故障回退分别建立范围，多实例不共享可变缓存，缓存不跨帧。

## 内存与确定性工作量

独立计数使用真实 Canvas，RGB 和 Coverage 按唯一 ArrayBuffer 容量合计，不包含 Canvas backing store、ImageData 和坐标表。冷布局结果如下：

| 尺寸 | 分配次数 前→后 | 持有字节 前→后 | 节省字节 |
| --- | ---: | ---: | ---: |
| 320×240 | 27→19 | 2,529,600→2,424,000 | 105,600（约 0.101 MiB） |
| 1950×1097 | 39→27 | 70,530,336→67,682,064 | 2,848,272（约 2.716 MiB） |

1950×1097 中非首层 scratch 节省 2,840,112 字节，末层 up 节省 8,160 字节。稳定布局前后均为零新增缓冲分配；切换 fewerLevels、moreLevels、shrunk、restored 后，当前最末层 up 容量均为 0，需要重新变成非末层时按原策略申请。完整切换记录保存在基准 JSON 的 bufferWork。

圆环使用两个同时出生的点击、四个圆环、20 帧独立计数。默认和相对 OKLCH 主题得到相同次数，生命周期推进场景包含溶解边界：

| 后端/生命周期 | 颜色求值 前→后 | 序列准备 前→后 | 圆锥渐变（不变） | conic stop（不变） |
| --- | ---: | ---: | ---: | ---: |
| Native 固定 | 62,080→15,520 | 640→160 | 640 | 62,080 |
| Native 推进 | 64,736→16,184 | 640→160 | 640 | 64,736 |

八个圆环场景的颜色求值和序列准备均减少 75%。Native 每 20 帧创建 160 份完成的序列，480 次命中；Software 创建 480 份，1,440 次命中。每帧结束释放，没有跨帧渐变缓存。纹理采样、边界二分及八次迭代均未减少；缓存 miss、hit 的全部 stop 写入顺序保持一致。

Software 独立诊断的默认、圆角碎片、visual-max、Alpha=1 普通和颜色补偿场景，前后的全部调用计数及有界主画布操作轨迹深度比较一致。默认 20 帧仍回读 100 次，请求 4,576,160 像素，返回 18,304,640 字节；写回 300 次，drawImage 1,600 次。单帧轨迹的 clear、draw、getImageData、putImageData 顺序不变，无截断或采集错误。滤波工作量完整对照也相同。独立核对结果为 `test-results/stage12-evidence.json`，不以耗时作为这些检查的通过条件。
